## Key facts learned
1. **Vercel installs only `[project.dependencies]`; an optional extra is
   ignored.** This was the whole first-deploy failure: `psycopg` in the `server`
   extra → `ModuleNotFoundError` → `FUNCTION_INVOCATION_FAILED` on every request.
   The build log gave no hint ("Installing required dependencies from
   pyproject.toml" then "Build Completed"). Fix: base dependency. A
   `requirements.txt` is not consulted when `pyproject.toml` exists.
2. **Serverless needs a stable Postgres schema.** Each request builds a new
   `PostgresStore`; the default random schema per instance reads an empty DB.
   Added `TAPEJUDGE_DB_SCHEMA`.
3. **Use the unpooled Neon endpoint.** `PostgresStore` keeps one connection per
   instance and does a session-level `SET search_path`; a transaction-mode
   PgBouncer (pooled) endpoint does not preserve session state. Both endpoints
   happened to work in a quick probe, but unpooled is the correct choice.
4. **Supabase free tier is capped at 2 active projects account-wide** → could
   not create one. Vercel's Neon marketplace integration is the free unblock:
   `vercel integration accept-terms neon --yes` then `vercel integration add neon`
   (the plain `add` opens a browser for terms; `accept-terms` is the
   non-interactive path for Neon).
5. Vercel project + env vars can be driven entirely by the REST API with
   `$VERCEL_TOKEN`; `vercel integration add neon` writes ~18 `*_URL`/`PG*` env
   vars into the project automatically.
6. The `vercel git connect --yes` command works with the CLI token — the earlier
   reported "GitHub integration 401" blocker is gone.
7. Pushing to GitHub: the git credential helper does not supply the token
   non-interactively; set the remote URL to
   `https://${GITHUB_TOKEN}@github.com/itzebe/tapejudge.git` to push, then reset
   it to the clean URL.
